# 《领域驱动设计》蓝皮书 · 5 天入门学习计划

> 对应书籍：Eric Evans《领域驱动设计：软件核心复杂性应对之道》（Domain-Driven Design，俗称蓝皮书）

## 这本书在讲什么（一句话）

软件复杂度往往在「业务」而不在技术。DDD 教你用**统一语言**和**领域模型**，把业务知识稳定地落到代码结构里，而不是先堆框架。

## 先建立总图（开读前半小时）

记住三条线：

1. **战略设计**：大图怎么切——限界上下文、上下文映射、核心域 vs 支撑域 / 通用域
2. **战术设计**：一个上下文里怎么建模——实体、值对象、聚合、仓储、领域服务、领域事件
3. **协作方式**：业务专家与开发用**同一套词**持续对话、重构模型

书偏「思想与模式」；落地案例可对照 Vaughn Vernon《实现领域驱动设计》（红皮书），但 5 天先吃透蓝皮书主线即可。

## 5 天学习计划（每天约 2–3 小时）

### Day 1 · 为什么需要 DDD + 统一语言

- **目标**：明白「复杂在哪」「模型是什么」
- **读**：前言 / 第一部分「运用领域模型」相关章节（知识消化、模型驱动设计、统一语言）
- **练**：选一个你熟的业务（如订单、车辆监管、客服工单），列出业务词表；标出开发与业务说法不一致的词
- **验收**：能用业务语言讲清「这个系统到底解决什么问题」

### Day 2 · 模型驱动设计的积木（战术入门）

- **目标**：分清实体 / 值对象 / 服务 / 模块
- **读**：模型驱动设计相关章节（实体、值对象、服务、模块）
- **练**：把昨天的词表映射成类型——哪些有唯一身份（实体）、哪些只看属性（值对象）、哪些是无状态的领域行为（领域服务）
- **验收**：举 3 个值对象例子（如金额、地址、时间区间），说明为何不该做成「带 id 的表」

### Day 3 · 聚合、仓储、生命周期

- **目标**：理解「一致性边界」和「怎么取存模型」
- **读**：聚合、工厂、仓储、生命周期
- **练**：画 1–2 个聚合根及边界；写清「哪些改动必须同事务」「哪些只能通过根访问」
- **验收**：能解释：为什么不能随意在 `Order` 里直接乱改深层子对象；仓储接口为何面向领域而不是 SQL

### Day 4 · 战略设计：限界上下文与映射

- **目标**：从「一个大模型」走向「多个有边界的模型」
- **读**：限界上下文、上下文映射（防腐层、开放主机、共享内核、客户-供应商等）、蒸馏（核心域）
- **练**：把你的系统画成 3–6 个上下文；标集成关系；标出核心域（最值得深挖建模的）
- **验收**：能说清「用户 / 订单」在不同上下文含义不同时怎么处理，而不是一张 User 表打天下

### Day 5 · 柔性设计 + 落地检查清单

- **目标**：知道模型如何演进、和实现怎么对齐
- **读**：柔性设计（意图显现、副作用、断言等）、大型结构 / 演进相关章节；回顾全书
- **练**：用检查清单审视一个真实模块：语言统一吗？聚合过大吗？贫血模型吗？跨上下文有没有防腐？
- **验收**：写出一页「本团队 DDD 入门约定」（何时用聚合、何时用事务脚本就够）

## 核心概念速查（入门够用）

| 概念 | 要点 |
| --- | --- |
| **统一语言** | 代码名 = 讨论名 = 文档名 |
| **实体** | 有连续身份 |
| **值对象** | 无身份、不可变、可替换 |
| **聚合** | 一组对象的一致性边界；对外只通过聚合根 |
| **仓储** | 用领域方式获取聚合（像集合，不是 DAO 细节泄露） |
| **领域服务** | 放不进实体 / 值对象的领域行为 |
| **限界上下文** | 模型适用的边界；边界外换模型或翻译 |
| **核心域** | 竞争力所在，投入最多建模精力 |

---

## 常见坑

- 一上来就上事件溯源 / CQRS（先把语言和聚合边界找对）
- 所有类都加 Repository
- 一个巨型聚合 / 一个企业级万能模型
- 只有分层架构名词、没有业务语言

---

## 建议读法

蓝皮书可跳着读：先**统一语言与模型驱动** → **聚合仓储** → **限界上下文**；细节模式按需回翻。每天结束用自己的业务画一图，比抄笔记更有效。

---

## Day 5 可用检查清单（模板）

- [ ] 关键业务词是否在代码 / 文档 / 口头讨论中一致？
- [ ] 实体与值对象是否分清？有没有「为了落库硬加 id」？
- [ ] 聚合边界是否过小或过大？跨聚合修改是否误用同一事务硬绑？
- [ ] 仓储是否泄露 SQL / ORM 细节给领域层？
- [ ] 是否存在跨限界上下文的「万能模型 / 共享大表」？
- [ ] 核心域是否被当成普通 CRUD 对待？
- [ ] 复杂处是领域规则，还是贫血模型 + 一堆 if？
