# PKI 知识梳理

> 结合《X.509 PKI 系统功能模块接口文档》（终端设备 / 国密网关 / TSP / X.509 系统）整理。

## 1. PKI 是什么

PKI（Public Key Infrastructure，公钥基础设施）是一套用公钥、私钥和数字证书来**证明身份、加密通信、防篡改**的体系。

核心是**数字证书**：由受信任的 CA 签发，把「公钥」和「某个身份」绑定在一起。

一句话：PKI 解决的是「这个公钥到底是谁的，能不能信」。

常见用途：

- HTTPS 网站证书
- 代码签名、邮件签名
- 企业内网登录、VPN
- 设备身份认证（车联网终端等）

## 2. PKI 中的角色

| 角色 | 作用 |
|------|------|
| CA（证书颁发机构） | 签发、更新、吊销证书。一般分根 CA 和中间 CA |
| RA（注册机构） | 审核申请人身份，通过后交给 CA 签发 |
| 终端实体（证书持有者） | 网站、人、设备，持有私钥和证书 |
| 依赖方 | 验证证书的一方，如浏览器、网关 |
| 证书库 | 存放证书和吊销列表（CRL） |
| 验证服务 | 在线查询证书状态，常见是 OCSP |

一句话：RA 核身份，CA 发证，持有者用证，依赖方验证，证书库和 OCSP 负责「证书还有没有效」。

## 3. 文档中的系统架构

```mermaid
flowchart LR
    T[终端设备] <-->|国密双向 TLS| G[国密网关]
    G <--> P[TSP 平台]
    P <--> C[X.509 系统 / CA]
```

| 系统 | 在 PKI 中的角色 | 职责 |
|------|------------------|------|
| 终端设备 | 证书持有者 | 预置根证书、生成密钥和 P10、发起申请、使用设备证书 |
| 国密网关 | 安全通道 / 依赖方 | 与终端做国密双向 TLS，转发申请、下载、回执报文 |
| TSP 平台 | 接近 RA | 设备序列号入库、校验 `identNo`、转发 P10、下发证书、保存绑定关系 |
| X.509 系统 | CA | 签发、更新、吊销、挂起、解挂证书 |

### PKI 和 TSP 的关系

- PKI 是整套证书体系和能力。
- TSP（Telematics Service Provider，车联网服务平台）是这套体系里的业务平台，一般扮演 RA。
- TSP **不签发证书**，它管设备身份和业务，CA 管发证。

## 4. 证书生命周期（文档主线）

### 4.1 终端获取证书流程

1. TSP 收集并存储终端设备序列号（SN）。
2. 终端 SDK 预置根证书。
3. 终端与国密网关建立双向 TLS。
4. 终端生成密钥对和 P10 请求（CN = 设备号 `identNo`），经网关发给 TSP。
5. TSP 校验申请里的 `identNo` 是否和序列号库中的 SN 对应。
6. 校验通过后，TSP 把 P10 发给 X.509 系统。
7. X.509 系统签发证书，返回 TSP。
8. TSP 校验证书 CN 等于 `identNo`，保存「设备 SN ↔ 证书序列号」绑定关系。
9. 终端发送证书下载请求，经网关到 TSP，TSP 返回证书。
10. 终端校验证书有效后，上报证书接收状态。

### 4.2 其他生命周期功能

| 功能 | 说明 |
|------|------|
| 证书更新 | 证书快到期或需要换证时，重新申请、下载、上报接收状态 |
| 证书吊销 | 证书永久作废（设备报废、私钥泄露等） |
| 证书挂起 | 临时冻结证书 |
| 证书解挂 | 恢复被挂起的证书 |
| 证书查询 | 查询证书和状态 |

### 4.3 关键接口（来自文档）

| 方向 | 接口 | 用途 |
|------|------|------|
| TSP → X.509 系统 | `POST /api/open/business/certApply` | 提交 P10，获取证书 |
| 国密网关 → TSP | `POST /basic/apply/request/certApply` | 终端证书申请 |
| 国密网关 → TSP | `POST /basic/apply/request/certDownload` | 终端证书下载 |

申请主要字段：`certType`、`identType`、`identNo`、`duration`（月，默认 24）、`p10`。

返回主要字段：`dn`、`serialNo`、`signCert`（PEM 签名证书）、`rootCert`（PEM 根证书）、`code`、`message`。

## 5. 根证书

### 5.1 谁预置根证书

**终端设备预置**，不是 TSP，也不是网关的业务配置。文档写的是「终端设备 SDK 预制根证书」。

常见预置方式：

- 写进固件 / SDK
- 烧进安全芯片、TEE 或 SE
- 产线工具灌入，量产后禁止随意修改

### 5.2 根证书是否相同

- 同一家 CA、同一套 PKI 体系下，**所有终端预置的是同一张根证书**。
- 网关装的根（或信任链）和终端的根**也是同一套**。
- 每台设备不同的是**设备证书**：CN 是各自的设备号，序列号也不同。
- 换一家 CA，终端和网关都要换成对应的根。

### 5.3 申请证书时会不会重复生成根证书

**不会。** 根证书是 CA 的，长期固定。

每次申请只签发一张新的设备证书。接口返回的 `rootCert` 只是把同一张根再下发一次，方便终端校验。

## 6. 国密网关

### 6.1 是什么

终端设备和 TSP 之间的安全通道，**不是发证机构**。支持国密算法（SM2 / SM3 / SM4）和国密 TLS。

### 6.2 作用

- 与终端做国密双向 TLS：网关验设备证书，设备用预置根证书验网关。
- 加密链路，并让双方互相确认身份。
- 把证书申请、下载、回执报文转给 TSP。

它**不签发证书**，也**不保存**设备号和证书的绑定关系。

### 6.3 网关需要安装什么

- 自己的**服务器证书和私钥**
- 用来验证设备证书的**同一套 CA 根 / 中间证书**

网关**不需要、也不应该**持有终端的私钥。

### 6.4 网关私钥怎么产生

1. 在网关本地（或密码卡、密码机）生成 SM2 密钥对，私钥不出本地。
2. 用私钥签出 P10，CN 一般填网关域名或 IP。
3. 提交 CA 签发服务器证书，再装回网关。

国密 TLS 一般有两套证书：

- **签名证书**：私钥由网关自己生成。
- **加密证书**：加密密钥对按规范多由 CA 侧的密钥管理中心（KM）生成，再加密下发。

具体以对接的 CA 和网关厂商为准。

### 6.5 常见形态和厂商

| 形态 | 说明 |
|------|------|
| 硬件网关 | 机房里的 SSL VPN / 应用安全网关，带密码卡或密码机 |
| 软件 / 虚拟化 | 跑在虚拟机或容器里，可调用密码机 |
| 云上产品 | 云厂商的国密 SSL 网关或 VPN |

常见厂商：信安世纪、三未信安、卫士通、江南天安、吉大正元、深信服、奇安信、华为、天融信；云上有阿里云、腾讯云、华为云等。

## 7. 证书申请由谁发起

**一般由终端设备自己发起**：

1. 在本地生成密钥对。
2. 用私钥签出 P10（CN 填设备号）。
3. 经国密网关发给 TSP，TSP 校验后转给 CA。

私钥始终不离开设备，所以 TSP 只能代为转交，不能替设备生成私钥。

产线批量灌证时，也是由产线工具在设备上生成密钥再统一提交，本质上仍由设备持有私钥。

## 8. 终端用 MQTT / TCP 连接云端

终端不直连云端业务，而是先和国密网关建立国密双向 TLS，再在这条通道上跑业务协议。

1. 出厂时 SDK 预置根证书。
2. 终端生成密钥和 P10，经网关向 TSP 申请证书，再下载安装。
3. 连接时用设备证书与网关做双向 TLS。
4. TLS 建好后，MQTT（通常 8883）或自定义 TCP 报文走这条加密通道，网关再转到后台。

MQTT 和 TCP 只是 TLS 之上的业务协议，**身份和加密靠证书**，不靠明文端口。

## 9. 国内 CA 机构

国内提供电子认证服务需要两张牌：

- 工信部《电子认证服务许可证》
- 国家密码管理局《电子认证服务使用密码许可证》

完整名单可查：

- [工信部许可的 CA 机构名单](https://www.miit.gov.cn/cms_files/filemanager/1226211233/attach/20228/82a5f16114024635b75fbaf4497278b6.pdf)
- [国家密码管理局许可查询](http://sca.gov.cn/app-zxfw/xzspsx/syxkdw.jsp?channel_code=c100142)

做车端国密证书时常见对接的有：

- 中金金融认证中心（CFCA）
- 北京数字认证（北京 CA）
- 北京天威诚信
- 沃通
- 数安时代
- 上海 CA
- 国汽（北京）智能网联汽车研究院

## 10. 建设 TSP 平台需要的能力

TSP 不是 CA，不需要自己发证，但需要把终端和 CA 串起来：

1. **设备身份库**：采集、存储设备序列号，申请时核对 `identNo`。
2. **证书生命周期管理**：申请、下载、接收确认、更新、吊销、挂起、解挂、查询。
3. **国密能力**：支持 SM2 P10、PEM 证书处理，配合国密网关完成双向 TLS。
4. **绑定关系管理**：校验证书 DN / CN，保存设备 SN 与证书序列号的绑定。
5. **对接持牌 CA**：调用 CA 的申请、更新、吊销接口，不自建根 CA。

自建 CA 需要上述两张许可证，以及根证书、密钥管理系统和审计体系，和建设 TSP 不是一回事。

## 11. 给客户讲 PKI 的提纲

按「干什么 → 谁参与 → 核心功能 → 怎么落地」讲：

1. **解决什么问题**：身份认证、加密传输、防篡改。
2. **角色关系**：终端、国密网关、TSP、CA。
3. **核心功能**：申请、下发、接收确认、更新、吊销、挂起、解挂、查询、双向 TLS。
4. **系统对应**：TSP 管设备和绑定，CA 管签发，网关管通道，MQTT / TCP 跑在 TLS 之上。
5. **落地问题**：根证书预置方式、设备号入库、有效期与更新策略、吊销生效时间、是否支持 SM2。

## 12. 速记

- 根证书：CA 的，固定不变，终端和网关信任同一套。
- 设备证书：每台设备一张，CN = 设备号。
- 私钥：谁用谁生成，不出本地。
- TSP：管身份和业务，接近 RA。
- X.509 系统：真正的 CA，负责签发。
- 国密网关：管加密通道和双向认证，不发证。
