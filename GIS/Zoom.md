# Zoom（缩放级别）

Zoom（缩放级别）是 Web 地图中最基础的概念之一：它用一个**整数（或小数）** 描述当前地图放大到了什么程度。所有在线地图（高德、百度、Google、OSM、Mapbox）底层的瓦片调度、分辨率、比例尺都围绕 zoom 展开。

> Zoom 解决的是“看多大范围、多精细”的问题。它和 [[H3]] / [[Geohash]] 解决的“如何索引空间”是两个维度：zoom 关乎**展示与瓦片**，H3/Geohash 关乎**聚合与查询**，但二者经常配合使用。

## 1. zoom 的本质

主流 Web 地图采用 **Web Mercator 投影（EPSG:3857）**，并把世界铺成一个金字塔式的瓦片网格：

- **zoom 0**：整个世界用 **1 张 256×256** 的瓦片表示。
- **每升高 1 级**，横向、纵向各切一刀，瓦片数量翻倍，**地面分辨率（每像素代表的米数）减半**。

因此第 $z$ 级有 $2^z \times 2^z = 4^z$ 张瓦片：

| zoom | 瓦片数（$4^z$） | 含义             |
| ---- | --------------- | ---------------- |
| 0    | 1               | 一张图看全球     |
| 1    | 4               | 2×2              |
| 5    | 1,024           | 大区             |
| 10   | 1,048,576       | 城市级           |
| 15   | 约 10.7 亿      | 街道级           |
| 18   | 约 6.87 × 10¹⁰  | 楼栋级           |

> 瓦片量随 zoom **指数增长**，这也是地图服务必须按 zoom 分层切片、按需加载的根本原因。

## 2. zoom 与分辨率 / 比例尺

### 2.1 地面分辨率

赤道处每像素代表的米数（ground resolution）：

$$
\text{resolution}(z) = \frac{2 \pi R}{256} \cdot \frac{1}{2^z} = \frac{156543.03}{2^z} \;\text{米/像素}
$$

其中 $R = 6378137$ m（WGS84 长半轴）。注意分辨率随**纬度升高而变好**（Mercator 在高纬放大）：

$$
\text{resolution}(z, \text{lat}) = \frac{156543.03 \cdot \cos(\text{lat})}{2^z}
$$

### 2.2 比例尺

假设屏幕 DPI = 96：

$$
\text{scale} \approx \text{resolution}(z,\text{lat}) \times 3779.52
$$

### 2.3 标准对照表（赤道处）

| zoom | 分辨率（米/像素） | 比例尺约值   | 典型视图     |
| ---- | ----------------- | ------------ | ------------ |
| 0    | 156,543           | 1 : 5.9 亿   | 全球         |
| 1    | 78,272            | 1 : 2.95 亿  |             |
| 3    | 19,557            | 1 : 7400 万  | 国家/大区    |
| 5    | 4,892             | 1 : 1848 万  | 省           |
| 8    | 611               | 1 : 231 万   | 城市         |
| 10   | 152               | 1 : 57.6 万  | 城区         |
| 13   | 19.0              | 1 : 7.2 万   | 街道         |
| 15   | 4.77              | 1 : 1.8 万   | 路网细节     |
| 17   | 1.19              | 1 : 4500     | 楼栋         |
| 19   | 0.30              | 1 : 1125     | 近景         |
| 20+  | 0.15 ~            | 1 : 562 ~    | 极精细       |

> 这张表和 [[H3]] 的分辨率表是两个体系：H3 的 res 0–15 是**索引层级**，zoom 0–20 是**显示层级**。实际工程里常做映射，例如“zoom 13 对应 H3 res 7 左右的派单网格粒度”。

## 3. 三种主流瓦片坐标系

不同的瓦片协议在“同一个 zoom”下，坐标定义并不一样，接入底图时容易踩坑：

| 协议                  | 原点     | y 轴方向 | 代表实现               |
| --------------------- | -------- | -------- | ---------------------- |
| **Google / OSM（XYZ）** | 左上角   | 向下增加 | 高德、Google、Leaflet、Mapbox |
| **TMS**               | 左下角   | 向上增加 | OSGeo TMS、部分老服务  |
| **WMTS**              | 左上角   | 用“瓦片矩阵集”定义 | OGC 标准、天地图、政府服务 |

Google 与 TMS 的 y 互换公式：

```
TMS_y = 2^z - 1 - Google_y
```

> 接第三方底图（尤其天地图、政府 WMTS）时，最常见的 bug 就是 **y 轴方向反转**，导致地图上下颠倒。先确认协议再接瓦片。

## 4. 各地图库的 zoom 接口

### 4.1 高德地图（AMap）

```js
const map = new AMap.Map('container', {
  zoom: 11,            // 初始缩放级别
  zooms: [3, 18],      // 允许的缩放范围
  center: [116.397428, 39.90923],
});

map.getZoom();         // 当前 zoom（可为小数）
map.setZoom(13);       // 设置 zoom
map.setZoomAndCenter(13, [116.397428, 39.90923]);
```

高德特点：

- zoom 范围通常 **3–18**（部分地区 19+），3 为全国，18 为楼栋级。
- **支持小数 zoom**（fractional zoom），缩放更平滑。
- zoom 与 [[热力图]] 参数（`radius`、`max`）需要联动调优。

### 4.2 Leaflet / Mapbox / OpenLayers

```js
// Leaflet
map.getZoom();          // 整数或小数
map.setZoom(13);
map.options.minZoom / maxZoom;

// Mapbox GL / MapLibre
map.getZoom();          // 默认支持小数 zoom
map.setZoom(13);
map.getMinZoom() / getMaxZoom();

// OpenLayers
view.getZoom();
view.setZoom(13);
```

现代库基本都支持**小数缩放**，这意味着可以在任意精度连续放大。

## 5. zoom 与地图内容的联动

zoom 不只是“放大缩小”，它直接决定了地图**渲染什么内容**：

### 5.1 底图样式分层

矢量瓦片会按 zoom 定义不同的样式规则，例如：

- 低 zoom（3–5）：只显示国家/省界、大城市。
- 中 zoom（8–11）：显示城市路网主干、区县。
- 高 zoom（13–15）：显示街道、POI、地标。
- 极高 zoom（17+）：显示建筑物轮廓、室内。

### 5.2 数据可视化的分层（与 [[热力图]] 配合）

车联网 / 业务系统常见组合：

| zoom 范围 | 推荐展示方式              | 理由                         |
| --------- | ------------------------- | ---------------------------- |
| 3–8       | 热力图 / H3 大网格聚合    | 看全局趋势，单点无意义       |
| 9–12      | 点聚合 / H3 res6–7 网格   | 开始能看出区域分布           |
| 13–15     | 聚合点 → 散点过渡         | 数据量可控，可看明细         |
| 16+       | 散点 / 车辆实时位置       | 精确到楼栋、车道             |

> 这与 [[热力图]] 第 9 节的思路一致：**缩小时看趋势（热力图），放大后看明细（散点）**，zoom 是切换展示策略的触发器。

## 6. zoom 的工程注意点

### 6.1 minZoom / maxZoom 要和业务匹配

- 设太小：底图瓦片没有，放大是空白。
- 设太大：服务端没切片到这个级别，出现马赛克。
- 建议：`maxZoom` 不超过底图实际切片的最大级别。

### 6.2 zoom 不是精确比例尺

Web Mercator 在高纬度变形严重，**zoom 对应的比例尺只在赤道附近准确**。国内业务（中纬度）实际分辨率比赤道值略好。需要精确比例尺时，必须结合纬度计算（见第 2.1 节）。

### 6.3 zoom 与数据加载量

zoom 升高 → 瓦片数指数增长 → 前端要渲染的要素暴增。两种应对：

- **矢量瓦片**：服务端按 zoom 裁剪、简化几何，只下发当前级别需要的数据。
- **后端聚合**：低 zoom 返回聚合结果（如 H3 网格统计），高 zoom 才下发明细。

### 6.4 坐标系别忘了

zoom 是显示概念，和坐标系（WGS84 / GCJ-02 / BD-09）是两回事。高德底图用 GCJ-02，原始 GPS 是 WGS84，混用会偏移——详见 [[热力图]] 第 8.1 节。

## 7. zoom 与空间索引的关系（重点理解）

zoom（显示）和 [[Geohash]] / [[H3]]（索引）看似无关，实则是**同一思想的两套实现**——都是“分层级、按范围划分空间”：

| 概念      | zoom 体系        | Geohash 体系      | H3 体系             |
| --------- | ---------------- | ----------------- | ------------------- |
| 层级数    | 0–20（显示）     | 1–12（字符串长度）| 0–15（分辨率）      |
| 细分方式  | 每级 ×2（方形）  | 每位 ×2 或 ×8     | 每级 ×7（六边形）   |
| 用途      | 决定**展示**粒度 | 决定**查询**粒度  | 决定**聚合**粒度    |
| 是否等价  | ——               | 矩形索引          | 六边形索引          |

实践建议：**让索引粒度跟随 zoom 变化**。例如 zoom 8 用 H3 res4 做城市级聚合，zoom 13 切到 H3 res7 做派单级聚合，避免“低 zoom 下发海量小网格”的性能问题。

## 8. 总结

- **zoom 是 Web 地图的缩放刻度**，0 看全球，每升一级瓦片数 ×4、分辨率减半。
- **三种瓦片协议**（Google/XYZ、TMS、WMTS）的 y 轴方向不同，接底图要确认。
- **zoom 决定渲染什么**：低 zoom 看趋势（热力图/聚合），高 zoom 看明细（散点）。
- **zoom 不等于精确比例尺**，高纬度有变形；精确计算需结合纬度。
- **zoom（显示）与 H3/Geohash（索引）是两套层级体系**，工程上常按 zoom 动态切换索引粒度。
