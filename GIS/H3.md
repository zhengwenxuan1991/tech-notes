# H3

H3 是 Uber 开源的**全球离散六边形网格系统**（Discrete Global Grid System, DGGS），将地球表面用多层级的**六边形（Hexagon）**铺满，每个六边形都拥有一个唯一的层级化索引。

> 与同为空间索引的 [[Geohash]]（矩形 + Z 阶曲线）相对，H3 用六边形重新定义了网格的形状与拓扑。算法思路详见 [[Geohash 算法原理]] 作为对照。

## 1. 核心术语速查

后文会反复出现这些词，先一次性定义清楚（细节在对应章节展开）：

| 术语 | 别名 | 一句话定义 |
| --- | --- | --- |
| **Cell** | 单元 / 网格 | H3 网格的**基本单元**，就是一个六边形（极少数为五边形），代表地球表面一小块区域。一个 Cell 是其覆盖范围内所有坐标的“网格地址”。 |
| **H3 Index** | Cell Index | Cell 的**唯一标识**，一个 64 位整数，常以十六进制字符串展示，如 `89283082803ffff`（详见 §3）。 |
| **Resolution** | res / 分辨率 | 网格**层级**，0–15 共 16 级。级别越高格子越小、越精细（详见 §4）。 |
| **Base Cell** | 基础格子 | 分辨率 0 的 **122 个起始六边形**，铺在二十面体上，是所有更细网格的“根”。 |
| **Aperture** | 孔径 | 父子层级间的**细分比**，H3 固定为 **7**——一个父六边形细分成 7 个子六边形。 |
| **Hexagon / Pentagon** | 六边形 / 五边形 | Cell 的两种形状。绝大多数是六边形；为保证球面无缝闭合，二十面体顶点处保留 **12 个五边形**。 |
| **Icosahedron / Face** | 二十面体 / 面 | H3 把地球贴在一个**正二十面体**上，20 个三角面是网格的几何基底。 |
| **Grid Disk** | 网格盘 | `gridDisk(cell, k)`：中心 + 周围 k 圈，共 $3k(k+1)+1$ 个 Cell，用于半径查询（详见 §5.1）。 |
| **Grid Ring** | 网格环 | `gridRingUnsafe(cell, k)`：只取第 k 圈的环，不含内部。 |
| **Parent / Child** | 父格子 / 子格子 | 跨层级关系。`cellToParent` 上溯、`cellToChildren` 下钻，几何上无损（详见 §5.2）。 |
| **Directed Edge** | 有向边 | 两个相邻 Cell 之间的**单向连接**（A→B），用于建模流向 / 路网邻接，有独立的索引模式。 |
| **Compact** | 压缩 | `compactCells`：按父子关系把一堆细格子合并成更少的粗格子，省存储；`uncompactCells` 反之。 |
| **LatLng** | 经纬度 | WGS84 经纬度坐标，是 `latLngToCell` 的输入；注意国内坐标需先做 GCJ-02 转换。 |

> 一句话建立直觉：**地球 → 二十面体 → Base Cell（res 0）→ 逐层 ×7 细分 → 某一级的 Cell（一个六边形）→ 用 H3 Index 唯一编号**。换分辨率 = 换层级，同一坐标在不同 res 下落在不同的 Cell 里。

## 2. 为什么是六边形？

Geohash / S2 这类基于正方形网格的方案，相邻格子的关系比较“死板”。H3 选择六边形，核心动机是**邻居一致性**：

| 网格形状 | 相邻邻居数量 | 邻居关系             | 适用场景       |
| -------- | ------------ | -------------------- | -------------- |
| 正方形   | 8 个（含对角） | 边邻居距离 ≠ 角邻居距离 | 切片简单、SQL 友好 |
| 三角形   | 3 / 12 个    | 方向不均             | 极少使用       |
| **六边形** | **6 个（全等）** | **所有邻居中心距完全一致** | **路径、聚合、平滑插值** |

六边形的关键优势：

- **所有邻居等距**：6 个边邻居到中心的距离完全相同，没有“边邻居”和“角邻居”的区别，做半径查询、平滑扩散更自然。
- **各向同性**：六边形更接近圆形，相同面积下周长最短，边界效应弱，采样更均匀。
- **层级关系清晰**：一个六边形可精确细分为 7 个子六边形，支持多尺度分析。

> 代价：六边形**不能完美无缝铺满球面**，H3 通过引入 **12 个五边形**（放在二十面体顶点处）来解决球面闭合问题。绝大多数业务区域只碰得到六边形。

## 3. 索引结构（H3 Index）

H3 的坐标系统基于**二十面体（Icosahedron）**：把地球贴在 20 面体上，每个面再进一步细分为六边形网格。

一个 H3 索引是一个 **64 位整数**，封装成字符串后类似：

```
89283082803ffff
```

其内部由 4 部分组成：

| 字段            | 含义                                   |
| --------------- | -------------------------------------- |
| `reserved`      | 保留位                                 |
| `mode`          | 网格模式（Hexagon / FaceIJK 等）       |
| `resolution`    | 分辨率（0–15）                         |
| `base cell`     | 基础格子（二十面体的 122 个起始面）    |
| `digit / face`  | 每一层的细分路径，逐层定位             |

> 灵魂同 [[Geohash]]：**前缀（高位）相同 → 大格子相同 → 地理上靠近**，但 H3 的层级是“父子细分”而非“前缀字符串”。

## 4. 分辨率与精度

H3 共有 **16 级分辨率（0–15）**，每升一级，边长约为上一级的 $1/\sqrt{7}$，面积约为 $\frac{1}{7}$。

| 分辨率 | 平均边长      | 平均面积       | 典型用途          |
| ------ | ------------- | -------------- | ----------------- |
| 0      | 约 1,107 km   | 约 4.25 万 km² | 大洲级            |
| 1      | 约 418 km     | 约 6.10 千 km² | 国家级            |
| 2      | 约 158 km     | 约 868 km²     | 省级              |
| 3      | 约 60 km      | 约 124 km²     | 城市群            |
| 4      | 约 23 km      | 约 17.7 km²    | 城市级            |
| 5      | 约 8.5 km     | 约 2.53 km²    | 区县级            |
| 6      | 约 3.2 km     | 约 363 千 m²   | 街道/商圈级       |
| 7      | 约 1.2 km     | 约 51.9 千 m²  | **打车派单、车辆网格（推荐）** |
| 8      | 约 461 m      | 约 7.42 千 m²  | 精细网格、停车区  |
| 9      | 约 174 m      | 约 1.06 千 m²  | 精细轨迹          |
| 10     | 约 66 m       | 约 151 m²      | 行人级            |
| 11     | 约 25 m       | 约 21.5 m²     | 室外精细          |
| 12     | 约 9.4 m      | 约 3.07 m²     | 室内/车道级       |
| 13     | 约 3.6 m      | 约 0.44 m²     | 极精细            |
| 14     | 约 1.3 m      | 约 0.063 m²    | 接近单点          |
| 15     | 约 0.5 m      | 约 0.009 m²    | 子米级            |

> 车联网场景中，**res 6 / res 7** 是最常用的网格粒度，对应“商圈级”到“派单级”。这与 [[Geohash]] 文档里 geohash7（约 150m）的定位类似——网格适中、聚合量可控。

## 5. 核心特性

### 5.1 六边形邻居

H3 提供两类邻居接口：

- `gridDisk(h, k)`：以中心格子为圆心，向外扩展 k 圈，返回 $1 + 6 + 12 + \dots + 6k$ 个格子（k 圈共 $3k(k+1)+1$ 个）。
- `gridRingUnsafe(h, k)`：只取第 k 圈的环。

```
       k=0        k=1              k=2
        ○        ○○○            ○○○○○
                ○○○○          ○○○○○○○
                ○○○○○          ○○○○○○○○
                ○○○○          ○○○○○○○
                  ○○○            ○○○○○
```

> 与 [[Geohash]] 的“边界突变”问题相比，H3 的 `gridDisk` 天然覆盖周围一圈，**不需要手动计算 8 个邻居**，半径查询更干净。

### 5.2 父子层级

- `cellToParent(h, res)`：取指定分辨率的父格子。
- `cellToChildren(h, res)`：取所有子格子（数量按 $\frac{1}{7}$ 倍数膨胀）。

一个父六边形精确细分成 **7 个**子六边形（含 1 个中心 + 6 个外圈），所以跨层级的聚合是无损的几何关系。

### 5.3 网格到多边形 / 多边形到网格

- `latLngToCell(lat, lng, res)`：坐标 → H3 索引。
- `cellToBoundary(h)`：H3 索引 → 六边形顶点坐标（可绘制）。
- `polygonToCells(geojson, res)`：任意多边形 → 覆盖它的所有 H3 索引。

这使得 H3 非常适合做**多边形覆盖**（如行政区划、自定义围栏），相比 Geohash 的矩形锯齿边界，六边形贴合度更高。

## 6. 与 Geohash 的对比

| 维度          | [[Geohash]]                 | **H3**                         |
| ------------- | --------------------------- | ------------------------------ |
| 网格形状      | 矩形（长方形）              | 六边形（+ 12 个五边形）        |
| 空间填充曲线  | Z-阶曲线                    | 基于二十面体的层级细分         |
| 邻居关系      | 边邻居 ≠ 角邻居距离         | 6 个邻居全等距                 |
| 索引类型      | 字符串（Base32）            | 64 位整数（字符串表示）        |
| 前缀查询      | ✅ 天然支持 `LIKE 'prefix%'` | ❌ 无字符串前缀语义，层级靠 API |
| SQL 友好度    | ✅ 极高（MySQL/ES/Doris 原生） | ⚠️ 需库或 UDF 支持              |
| 边界突变      | 严重，需算 8 邻居           | 轻微，`gridDisk` 直接覆盖      |
| 多边形覆盖    | 矩形锯齿                    | 六边形贴合更好                 |
| 典型场景      | 附近的人、外卖配送、Doris/ES | 打车派单、空间聚合、多边形覆盖 |
| 距离衰减建模  | 一般                        | 优秀（等距邻居）               |

一句话总结：

- **Geohash**：胜在**简单 + SQL 友好**，前缀匹配直接用 `LIKE`，适合直接落 Doris / ES / MySQL。
- **H3**：胜在**几何均匀 + 邻居等距**，适合需要“半径扩散、跨层级聚合、平滑插值”的分析场景，但需引入 H3 库。

## 7. 车联网 / 业务场景选型

| 场景                   | 推荐          | 理由                                   |
| ---------------------- | ------------- | -------------------------------------- |
| 附近的人 / 门店        | Geohash       | 前缀匹配简单，DB 友好                  |
| 区域统计 / 热力图      | H3 或 Geohash | H3 网格更均匀，[[热力图]] 效果更好     |
| 打车派单 / 车辆调度    | **H3**        | 等距邻居，半径扩散自然                 |
| 行政区 / 不规则围栏覆盖 | **H3**        | 多边形覆盖贴合度高                     |
| Doris / ES 直接查询    | Geohash       | 原生 `LIKE` + 索引                     |
| 跨层级下钻分析         | **H3**        | 父子层级无损，`cellToParent` 直接聚合  |

> 实际工程中常见组合：**后端用 H3 做网格聚合与分析，前端用 [[热力图]] / 聚合点渲染**。两者并不互斥。

## 8. 工程实践

### 8.1 官方绑定库

H3 由 Uber 维护，核心是 C 库，并提供了多语言官方绑定：

- **Java**：`com.uber.h3core`（`H3Core.newInstance()`）
- **Python**：`h3` 包
- **JavaScript**：`h3-js`
- **Go / Rust / C++** 等均有官方支持

```java
H3Core h3 = H3Core.newInstance();
long cell = h3.latLngToCell(39.9092, 116.3974, 7);          // 坐标 → res7 索引
List<Long> neighbors = h3.gridDisk(cell, 2);                 // 半径 2 圈邻居
String cellStr = h3.h3ToString(cell);                        // 89283082803ffff
List<LatLng> boundary = h3.cellToBoundary(cell);             // 六边形顶点
```

### 8.2 在数据库中使用

- **PostGIS**：`h3` 扩展，支持 `h3_lat_lng_to_cell`、`h3_grid_disk` 等。
- **Doris / ClickHouse**：可通过 UDF 或外置服务转换，常与 [[Doris GIS SQL 函数说明]] 的 `ST_*` 函数配合做两阶段过滤。
- **Redis / Elasticsearch**：已有社区插件支持 H3 字段类型与聚合。

### 8.3 精度选型建议

| 业务           | 推荐分辨率 |
| -------------- | ---------- |
| 城市级大盘统计 | res 4–5    |
| 商圈 / 区域聚合 | res 6      |
| **派单 / 车辆网格** | **res 7**  |
| 精细轨迹 / 停车 | res 8–9    |

> 选型原则与 [[Geohash]] 一致：H3 只是**空间索引精度**，不是真实空间精度。精确判断（是否在围栏内）仍需 `ST_CONTAINS`，H3 的目标是**收敛候选集、降低精确计算次数**。

## 9. H3 的局限

- **不能完美无缝铺球面**：12 个五边形是几何必然，极地附近可能出现非六边形，但业务上几乎无感。
- **SQL 原生支持弱**：相比 Geohash 的 `LIKE`，H3 需要专用函数 / UDF，对纯 SQL 团队有学习与接入成本。
- **无字符串前缀语义**：不能像 Geohash 那样直接用字符串前缀做范围扫描，必须走 H3 API。
- **存储为整数**：虽然是 64 位整数，但若数据库未原生支持，需以字符串形式存储，需注意索引方式。
