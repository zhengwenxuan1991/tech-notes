# 02 · 常用命令速通

> 上一篇：[基础概念](01-基础概念-工作区暂存区仓库.md) · 下一篇：[分支与合并](03-分支与合并.md)

按场景记命令，比背清单快。示例均在 `~/projects/git-lab`。

## 1. 看状态与差异

```bash
git status                 # 简明状态（建议配 git config status.short false 默认即可）
git status -sb             # 短格式 + 分支跟踪信息
git diff                   # 工作区 vs 暂存区
git diff --staged          # 暂存区 vs HEAD（也写作 --cached）
git diff HEAD              # 工作区+暂存 相对 HEAD 的总差
git log --oneline -n 20
git log --graph --oneline --decorate -n 30
git show HEAD              # 看某次提交的说明与补丁
git show <sha>:path/file   # 看历史版本里某个文件内容
```

## 2. 初始化与克隆

```bash
git init
git clone git@github.com:example/demo.git ~/projects/demo
git clone --depth 1 <url>  # 浅克隆，只要最近历史时
```

## 3. 暂存与提交

```bash
git add file.txt
git add .                  # 当前目录起所有变更（含删除）；大仓库慎用，先看 status
git add -p                 # 按块挑选
git commit -m "feat: add login"
git commit                 # 打开编辑器写多行说明
git commit --amend         # 改正上一次提交（说明或把漏 add 的补进去）
# amend 注意：若已 push 到共享分支，amend 后需要 force-push，协作时慎用
```

**提交说明建议**（团队可统一 conventional commits）：

```text
feat: 用户登录
fix: 修复空指针
docs: 补充 README
chore: 调整忽略规则
```

## 4. 撤销与还原（未推送场景优先）

```bash
# 撤暂存，保留工作区改动
git restore --staged file.txt
# 旧写法：git reset HEAD file.txt

# 丢弃工作区相对暂存区/HEAD 的改动（不可恢复）
git restore file.txt
# 旧写法：git checkout -- file.txt

# 软/硬回退整笔提交：见 08-reflog与回退
```

`git reset` 与 `git restore` 分工：

| 目标 | 更合适的命令 |
|------|----------------|
| 移动分支尖 / 改提交历史位置 | `reset` |
| 只改工作区或暂存区里的文件内容 | `restore` |

## 5. 删除、移动、忽略

```bash
git rm file.txt            # 删文件并暂存删除
git rm --cached file.txt   # 停止跟踪，本地文件留下（常配合 .gitignore）
git mv old.txt new.txt

# .gitignore 示例
echo "node_modules/" >> .gitignore
echo ".env" >> .gitignore
git add .gitignore && git commit -m "chore: ignore deps and env"
```

已跟踪的文件被 ignore **不会**自动失效，需 `git rm --cached`。

## 6. 配置（本机一次）

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global core.editor "vim"
git config --global pull.rebase false   # 或 true，团队统一即可
git config --global alias.st "status -sb"
git config --global alias.lg "log --graph --oneline --decorate -n 30"
```

查当前生效配置：`git config --list --show-origin`。

## 7. 帮助与补全

```bash
git help commit
git commit -h
# 多数系统可开 shell 补全；macOS 可用 brew 的 bash/zsh completion
```

## 8. 日常最小闭环

```bash
git status -sb
git diff
git add -p
git commit -m "feat: ..."
git log -1 --stat
```

远程相关（`fetch` / `pull` / `push`）见 [06](06-远程协作.md)；分支见 [03](03-分支与合并.md)。

## 9. 小结

- 先 `status` / `diff`，再 `add`，再 `commit`。
- 新命令优先记 `switch` / `restore`；遇到老教程里的 `checkout` 能映射即可。
- `--amend`、硬重置只在清楚是否已共享后使用。
