# 06 · 远程协作

> 上一篇：[冲突处理](05-冲突处理.md) · 下一篇：[stash](07-stash.md)

## 1. 远程是什么

远程（remote）是一个命名的 URL，常见名：

| 名 | 含义 |
|----|------|
| `origin` | 默认克隆来源，通常是你有推送权的仓库 |
| `upstream` | Fork 场景下的父仓库（只读拉取），见 [Fork 同步](Fork项目同步父项目更新.md) |

```bash
git remote -v
git remote add origin git@github.com:example/demo.git
git remote set-url origin git@github.com:example/demo.git
```

## 2. fetch / pull / push

```mermaid
flowchart LR
  L[本地仓库] -->|push| R[远程仓库]
  R -->|fetch| L
  R -->|pull = fetch + 合并或 rebase| L
```

```bash
git fetch origin                 # 更新远程跟踪分支 origin/*，不改你工作区
git log HEAD..origin/main        # 远程有、本地无
git log origin/main..HEAD        # 本地有、远程无

git pull origin main             # 取回并合并进当前分支
git pull --rebase origin main

git push -u origin feature/login # 首次推送并设上游
git push                         # 之后直接推
```

远程跟踪分支：`origin/main` 是本地的**备忘指针**，只在 `fetch`/`pull` 时更新。

## 3. 上游分支（upstream）

```bash
git branch -vv
git switch feature/login
git push -u origin HEAD
# 或
git branch --set-upstream-to=origin/feature/login
```

## 4. 强制推送

```bash
git push --force-with-lease origin feature/login
# 优于 --force：若远程有你未见过的新提交会拒绝，减少覆盖别人
```

**禁止**对 `main` 等共享保护分支强推（除非紧急事故且团队授权）。

## 5. 典型协作流

1. `git switch main && git pull`
2. `git switch -c feature/xxx`
3. 开发、commit
4. `git fetch && git rebase origin/main`（或 merge，按规范）
5. `git push -u origin HEAD`
6. 开 PR/MR → 评审 → 合入
7. 本地：`git switch main && git pull`；删本地分支

## 6. 浅克隆与大仓库

```bash
git clone --depth 1 <url>
git fetch --unshallow          # 需要完整历史时
```

## 7. SSH 与 HTTPS

- SSH：`git@github.com:org/repo.git`，依赖本机钥匙
- HTTPS：易配合 credential helper / token

权限问题先查：远端 URL、钥匙是否加载、是否有写权限。

## 8. 小结

- `fetch` 只更新知识；`pull` 会动当前分支；`push` 分享本地提交。
- 强推用 `--force-with-lease`；公共分支不改写历史。
- Fork 双远程流程见专题笔记，本篇不重复。
