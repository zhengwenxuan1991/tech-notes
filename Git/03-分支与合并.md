# 03 · 分支与合并

> 上一篇：[常用命令](02-常用命令.md) · 下一篇：[rebase 与 merge](04-rebase与merge对比.md)

## 1. 分支是什么

分支 = 指向某个 commit 的**可变引用**（`refs/heads/<name>`）。创建分支几乎只是新建一个指针，成本极低。

```text
main:     A---B---C
                 \
feature:          D---E
```

`HEAD` 通常挂在当前分支名上，新 commit 会让该指针前进。

## 2. 创建、切换、列出

```bash
cd ~/projects/git-lab
git branch                     # 本地分支
git branch -vv                 # 含上游跟踪
git switch -c feature/login    # 创建并切换（推荐）
# 旧：git checkout -b feature/login

git switch main
git branch -d feature/login    # 已合并可删
git branch -D feature/login    # 强制删未合并分支（慎）
```

命名习惯（示例）：`feature/...`、`fix/...`、`hotfix/...`、`chore/...`。

## 3. 快进合并（fast-forward）

若 `main` 没有分叉上的新提交，合并 `feature` 时 Git 只需把 `main` 指针移到 `feature` 尖：

```bash
git switch main
git merge feature/login        # 可能是 fast-forward
```

历史仍是一条直线，**不会**多一个「合并提交」。

## 4. 三方合并（有分叉）

两边都有新提交时，Git 找共同祖先，做三方合并，通常产生 **merge commit**（两个父提交）：

```bash
git switch main
git merge feature/login
# 打开编辑器写合并说明后保存
```

```text
      A---B---C---M     main
           \     /
            D---E       feature
```

## 5. 常用合并选项

```bash
git merge --no-ff feature/login   # 即使可快进也造 merge commit（保留分支拓扑）
git merge --squash feature/login  # 把分支改动揉成工作区/暂存区，自己再 commit（无合并节点）
git merge --abort                 # 冲突中放弃本次合并
```

`--squash` 适合「功能分支只想进 main 一笔干净提交」；历史里看不到原分支节点。

## 6. 查看分支图

```bash
git log --graph --oneline --decorate --all -n 40
git show-branch
```

## 7. 保护主分支的习惯

- `main` / `master` 不直接开发；从最新 `main` 拉功能分支。
- 合并进 `main` 前：自测、必要时 rebase/merge 最新 `main`、开 PR/MR 评审。
- 删除已合并远程分支：`git push origin --delete feature/login`（见 [06](06-远程协作.md)）。

## 8. 与 Worktree

同一仓库多目录并行开发时用 worktree，不必来回 `stash` + `switch`，见 [Git Worktree 使用指南](Git%20Worktree%20使用指南.md)。

## 9. 小结

- 分支是便宜指针；合并有快进与三方合并两种结果形态。
- `--no-ff` / `--squash` 改变的是**历史长什么样**，按团队规范选。
- 冲突不是失败，是合并的正常路径 → [05](05-冲突处理.md)。
