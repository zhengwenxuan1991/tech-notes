# 05 · 冲突处理

> 上一篇：[rebase 与 merge](04-rebase与merge对比.md) · 下一篇：[远程协作](06-远程协作.md)

## 1. 冲突何时出现

同一文件同一区域被两边改成不同内容，三方合并无法自动抉择时，Git 标为 **unmerged**，停下等你。

merge、rebase、cherry-pick、apply stash 都可能冲突。

## 2. 冲突标记长什么样

```text
<<<<<<< HEAD
当前分支上的内容
=======
进来的另一方内容
>>>>>>> feature/login
```

- `<<<<<<<` 到 `=======`：你这边（merge 时是当前分支；rebase 时语义要看提示，别死记「HEAD 一定是对的」）
- `=======` 到 `>>>>>>>`：另一边

有的工具会显示「ours / theirs」——**rebase 与 merge 下 ours/theirs 含义相反**，以 `git status` 文案和实际内容为准。

## 3. 标准处理流程（merge）

```bash
git switch main
git merge feature/login
# 出现冲突
git status                     # 看哪些 unmerged
# 编辑文件，删掉 <<<<<< ====== >>>>>>，留下最终内容
git add path/to/file.ts
git commit                     # 完成合并提交（若合并已自动带说明可确认即可）
```

中途放弃：`git merge --abort`。

## 4. rebase 中的冲突

```bash
git rebase origin/main
# 每重放一笔都可能停
# 解决后：
git add path/to/file.ts
git rebase --continue
# 跳过当前这笔：git rebase --skip
# 全部放弃：git rebase --abort
```

## 5. 工具

```bash
git checkout --ours path      # 慎用：语义依赖 merge/rebase
git checkout --theirs path
git diff                      # 看未解决差异
# IDE：VS Code / IDEA 的冲突编辑器；git mergetool
git mergetool
```

二进制文件冲突：通常选一边整文件，或检出后重新生成。

## 6. 预防与减痛

- 功能分支寿命短；常跟 `main`。
- 大改格式（全文件 format）与逻辑改动拆开提交/PR。
- 约定同一区域谁主改；生成文件（lockfile）冲突按工具规范解决（如重新 `pnpm install`）。
- `.gitattributes` 可标 `merge=union` 等（少用，知道即可）。

## 7. 验证

```bash
git status           # 应无 unmerged
git diff --check     # 查是否还留冲突标记
# 跑测试 / 本地启动
```

## 8. 小结

- 冲突 = 需要人判断的差异，不是仓库坏了。
- 改完必须 `add`，再 `commit` 或 `rebase --continue`。
- 放弃合并/变基用 `--abort`，不要手动乱删 `.git`。
